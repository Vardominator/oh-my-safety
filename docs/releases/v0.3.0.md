# oh-my-safety v0.3.0

v0.3.0 expands oh-my-safety from a macOS privacy tripwire into a local-first
macOS and Linux endpoint safety agent. Existing Homebrew, launchd,
`oh-my-privacy`, and SwiftBar workflows remain supported.

## Highlights

- Native `amd64` and `arm64` Debian, RPM, portable tar, controller, and classic
  Snap artifacts are built and smoke-tested on matching GitHub-hosted runners.
- Continuous Linux monitoring uses a user-scoped systemd service and never
  enables itself before the first scan and baseline review.
- Local history, finding lifecycle, per-check scheduling, profiles, redacted
  bounded secret scanning, executable triage, and signed offline-intelligence
  bundles are available without a hosted scanning service.
- Native desktop alerts can be extended with explicitly enabled SendGrid,
  Telegram, WhatsApp, Discord, or generic HTTPS webhook delivery.
- The optional self-hosted organization controller supports one-use enrollment,
  grouped signed policy, redacted finding synchronization, administrative
  roles, and an audit trail. It has no remote-shell capability.
- SwiftBar output is reorganized for legibility, with prioritized findings,
  saved remediation details, one-click rechecks, and collapsed healthy checks.

## Installation and upgrades

- macOS/Homebrew users can upgrade normally after the v0.3.0 formula update
  reaches `main`: `brew update && brew upgrade oh-my-safety`.
- Linux users should choose the checksum-verified `.deb`, `.rpm`, tagged
  per-user installer, or signed APT repository documented in
  `docs/linux.md`.
- The signed APT archive is published at
  `https://Vardominator.github.io/oh-my-safety/apt`. Its dedicated signing
  fingerprint is `C409801C769AE605678AC763F667FC021600FE36`.
- The `.snap` files attached to this release are tested sideload packages.
  There is no Snap Store listing: classic-confinement approval is still
  required and may be denied.

Run `oh-my-safety doctor`, perform an initial offline scan, and review
persistence and network baselines before enabling continuous monitoring.
Package and source installations do not silently trust the machine's current
state.

## Security and privacy boundaries

- Core observation, scanning, correlation, evidence, and history remain local.
- External exposure checks and notification channels are opt-in and are blocked
  by offline and air-gapped profiles.
- Secret findings are redacted and fingerprinted; the product does not upload
  secret values or provide unsupported malware-removal claims.
- Release assets are published together with checksums under an immutable,
  signed Git tag. The GitHub release attestation and each attached asset are
  verified by the release pipeline before downstream APT publication.

## Known limitations

- The organization controller is an early self-hosted control plane, not an
  EDR, MDM, remote-attestation system, or HA service.
- Deep content scanning still relies on explicit opt-in adapters or trusted
  local rules. Automated destructive remediation is intentionally out of
  scope.
- Snap Store installation is unavailable pending Canonical name registration
  and classic-confinement review.
